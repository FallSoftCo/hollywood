# Purpose-native effect authority

The v3 native source preserves authority, actor, host, original delivery/claim,
generation, request, current native thread/turn, tool call and argument digest.
It adds the immutable accepted execution scope ID and independently observed
executor ID. nativeGoalId is null: a purpose-native context does not need a
synthetic legacy goal binding.

Validation rechecks the authenticated purpose token, enabled placement, current
role revision, accepting writer turn, exact accepted scope, running inference
permit and independently live executor under the current enrolled controller.
It runs within the domain mutation's existing authority fence and transaction.
No application prompt, reader interpretation, room membership or model final
text grants this authority.

Exactly one physical executor may remain undrained for an original work claim.
Stopped incarnations remain immutable. A later physical incarnation is not
proof that prior effects were undone, and unknown work requires explicit
reconciliation. Resident purpose processes do not permanently consume inference
slots or block a later completed work claim.

Context-system enrollment is an administrative command with original-operation
receipts. An identical complete configuration is recoverable without resetting
the bindings or histories; a different configuration requires explicit migration.
Authenticated readback exposes binding IDs and credential digests, never tokens.

The v3 runtime protocol is a deployment fence: earlier purpose runtimes are
rejected before they can start work against this changed executor contract.
Legacy v1/v2 native effect sources retain their separate validation paths.

A protected installation upgrade can be recorded through the existing enrolled
host controller as native runtime metadata. The immutable host-command receipt
attributes software versions and available capabilities to that service. It
preserves the original work and can make an idle, confirmed-terminal writer
eligible for one continuation. It cannot steer an active writer, clear
cancellation, grant permissions, create chat messages, or infer prior effects.
An unchanged original operation returns its receipt without another continuation.

Initial context enrollment also ingests pending addressed requests using their
existing event and delivery IDs. A request queued before the first agent process
exists is retained and consumed without another send.


## Purpose-native collaboration and causal peer follow-ups

Protected collaboration admits v3 sources only after enrolled-host relay
authentication, immutable accepted writer scope validation, current inference
permit, independently fresh executor observation and explicit physical grants.
Direct native mutations still require the writer credential. The derived
purpose binding never fabricates a legacy context/execution row.

An actual peer request back, sourced to the original outbound delegation,
carries peerContinuation/parentWorkId. The reader applies it to that unfinished
work across authorized rooms. A prior unadmitted misclassification can be
retained as superseded only at pending delivery generation zero with no execution
or child delegation. Required answers can become ready from verified writer
material before parent completion; only the responder publishes.

r22 PostgreSQL evidence is rollback-only with frozen native facts. The actual
private two-agent model continuation remains a separate acceptance gate. Neither
implies physical-phone, multihost, compaction or complete enterprise readiness.
